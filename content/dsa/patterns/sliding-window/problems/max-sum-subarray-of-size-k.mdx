## Problem

Given an array `nums` of `n` integers and an integer `k`, find the maximum
sum of any `k` consecutive elements.

**Constraints**

- `1 <= k <= n <= 10^5`
- `-10^4 <= nums[i] <= 10^4`

**Example**

```text
Input:  nums = [2, 1, 5, 1, 3, 2], k = 3
Output: 9
```

The best window is `[5, 1, 3]` with sum 9.

## Brute force

For every starting position, sum the next `k` elements and keep the
largest.

```cpp
int maxSumBruteForce(const std::vector<int>& nums, int k) {
    int best = std::numeric_limits<int>::min();
    for (int i = 0; i + k <= static_cast<int>(nums.size()); ++i) {
        int sum = 0;
        for (int j = i; j < i + k; ++j) {
            sum += nums[j];
        }
        best = std::max(best, sum);
    }
    return best;
}
```

It's correct, but it's O(n·k): for n = 10^5 and k = 10^5 that's 10^10
additions, far too many.

## Optimal: fixed sliding window

Notice what changes between consecutive windows: one element enters on the
right and one leaves on the left. Everything in the middle is shared. So sum
the first window once, then slide: add the entering element, subtract the
leaving one, record.

```cpp
int maxSumWindowK(const std::vector<int>& nums, int k) {
    int sum = 0;
    for (int i = 0; i < k; ++i) {
        sum += nums[i];
    }
    int best = sum;
    for (int i = k; i < static_cast<int>(nums.size()); ++i) {
        sum += nums[i] - nums[i - k];
        best = std::max(best, sum);
    }
    return best;
}
```

Each step does O(1) work, so the whole scan is one pass. This is the
smallest complete example of the pattern; every other window problem is a
variation on this bookkeeping, as collected in
[Sliding Window](/dsa/patterns/sliding-window).

## Complexity

| Approach | Time | Space |
| --- | --- | --- |
| Brute force | O(n·k) | O(1) |
| Fixed sliding window | O(n) | O(1) |
