---
title: "Sliding Window"
summary: "Reuse work from the previous step instead of recomputing a subarray or substring from scratch, turning many O(n·k) scans into a single O(n) pass."
---

Here is an observation worth a whole pattern. Take the windows `[2, 1, 5]`
and `[1, 5, 1]` out of an array. They share two of three elements, so
computing both sums from scratch means adding up the overlap twice. The
second window is just the first one, plus `1` entering on the right, minus
`2` leaving on the left. That adjustment costs one addition and one
subtraction.

Sliding window is the systematic use of that observation: whenever a
contiguous range shifts by one position, reuse everything that didn't change.
A window re-checked from scratch costs O(k); a window *updated* costs O(1).
Over an array of n elements, that difference is the whole game.

## How to spot it

Reach for a sliding window when a problem gives you any of these signals:

- You're looking for a **contiguous subarray or substring** (not a
  subsequence, which doesn't have to be contiguous).
- The phrase **"longest", "shortest", "maximum", or "count"** appears with a
  condition like "at most k distinct characters" or "sum at least target".
- A **fixed-size** group is involved: "every window of size k", "maximum of
  each group of 3".
- Adding or removing an element **doesn't invalidate the rest** of the
  window. This is the real test: if the condition on a window can't be
  updated incrementally, sliding won't work.

The pattern comes in two shapes, and the problem statement tells you which.

## Fixed window

The size is given ("window of size k"). Slide one position at a time: add
the entering element, subtract the leaving one, and record.

```cpp
// Maximum sum of any k consecutive elements.
int maxSumWindowK(const std::vector<int>& nums, int k) {
    int sum = 0;
    for (int i = 0; i < k; ++i) {
        sum += nums[i];
    }
    int best = sum;
    for (int i = k; i < static_cast<int>(nums.size()); ++i) {
        sum += nums[i] - nums[i - k];
        best = std::max(best, sum);
    }
    return best;
}
```

Notice the second loop does O(1) work per step. Without the trick you'd
re-sum all k elements at every position, which is O(n·k).

## Dynamic window

The size is *not* given; instead you're told a condition, and the window
grows and shrinks to satisfy it. The standard loop has two pointers: `right`
expands the window, and `left` shrinks it whenever the condition breaks.

```cpp
// Longest substring without repeating characters.
int longestUnique(const std::string& s) {
    std::unordered_set<char> inWindow;
    int best = 0;
    int left = 0;
    for (int right = 0; right < static_cast<int>(s.size()); ++right) {
        while (inWindow.count(s[right])) {
            inWindow.erase(s[left]);   // shrink until the duplicate is gone
            ++left;
        }
        inWindow.insert(s[right]);
        best = std::max(best, right - left + 1);
    }
    return best;
}
```

The invariant is the key: after the inner `while` finishes, the window
`left..right` always satisfies the condition. Every element enters once and
leaves at most once, so the two pointers together do O(n) work even though
there are two loops.

## When it doesn't fit

Sliding window only works when a window's state can be updated from the
edges. If moving one element forces you to re-examine the whole window (a
condition like "the window must remain sorted" that depends on everything
inside), the pattern collapses back to O(n²) or worse. It also doesn't apply
to subsequences, where you're free to skip elements; those usually need
dynamic programming or a different angle.

## The takeaway

Sliding window is a bookkeeping trick, not an algorithm: never recompute
what you can adjust. If you can answer "what changes when this element
enters or leaves?" in constant time, the problem is a window problem.
