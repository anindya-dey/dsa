## Problem

Given a reference to a node in a connected undirected graph, return a deep
copy of the graph. Each node holds a value and a list of neighbors.

**Constraints**

- The number of nodes is between 0 and 100.
- `1 <= Node.val <= 100`, unique per node.
- The graph is connected and undirected.

**Example**

```text
Input:  adjacency [[2,4],[1,3],[2,4],[1,3]]
Output: the same graph structure, with all-new nodes
```

## Brute force

A deep copy that ignores the "graph" part: recursively copy each neighbor
without tracking what has already been copied.

```cpp
Node* cloneNaive(Node* node) {
    if (node == nullptr) {
        return nullptr;
    }
    Node* copy = new Node(node->val);
    for (Node* neighbor : node->neighbors) {
        copy->neighbors.push_back(cloneNaive(neighbor));
    }
    return copy;
}
```

This does not terminate on any graph with a cycle. `A` copies `B`, which
copies `A`, which copies `B`... forever. The bug is the whole lesson: a
graph is not a tree, so "recurse into every neighbor" must be guarded by
memory of what has already been created.

## Optimal: DFS with a map from original to copy

Keep a hash map from each original node to its copy. Before copying a node,
check the map; if it exists, return the existing copy instead of making a
new one. This both terminates the recursion and, crucially, wires the
cycle correctly: the copy of `A` points to the copy of `B`, which points
back to the *same* copy of `A`.

```cpp
class Solution {
public:
    Node* cloneGraph(Node* node) {
        if (node == nullptr) {
            return nullptr;
        }
        auto it = copies_.find(node);
        if (it != copies_.end()) {
            return it->second;             // already copied: reuse, don't recurse
        }

        Node* copy = new Node(node->val);
        copies_[node] = copy;              // register BEFORE recursing

        for (Node* neighbor : node->neighbors) {
            copy->neighbors.push_back(cloneGraph(neighbor));
        }
        return copy;
    }

private:
    std::unordered_map<Node*, Node*> copies_;
};
```

The load-bearing line is `copies_[node] = copy` **before** the recursion.
Register the copy first, then fill its neighbors; that way, when a neighbor
recurses back to `node`, it finds the half-built copy and links to it
rather than looping. This is the same "mark before you recurse" discipline
as [flood fill](/dsa/patterns/matrix-and-grid-algorithms/problems/number-of-islands),
applied to object identity instead of grid cells.

A BFS version is equivalent: a queue of originals, a map of copies, and for
each dequeued original, copy its neighbors (creating copies on first sight)
and enqueue the originals. DFS is shorter; BFS avoids deep recursion on a
long chain of nodes.

## Complexity

| Approach | Time | Space |
| --- | --- | --- |
| Naive recursion | does not terminate | - |
| DFS with visit map | O(V + E) | O(V) |

Every node and edge is visited once, and the map holds one entry per node.
This problem is the cleanest demonstration of the difference between
traversing a tree and traversing a graph: the only change is a visited
map, and that single addition is what turns a non-terminating recursion
into a linear one.
