## Problem

Reverse the character array `s` **in place**. Modify the given array and
use only O(1) extra memory; do not create another array for the result.

**Constraints**

- `1 <= s.length <= 10^5`
- Each element is a printable ASCII character.

**Example**

```text
Input:  s = ["h", "e", "l", "l", "o"]
Output: ["o", "l", "l", "e", "h"]
```

The first and last characters exchange places, as do the second and
second-to-last. The middle character stays where it is.

## Brute force: copy backwards

A straightforward baseline reads from the end into a new array, then
moves that array into `s`:

```cpp
#include <utility>
#include <vector>

void reverseStringBrute(std::vector<char>& s) {
    std::vector<char> reversed;
    for (int i = static_cast<int>(s.size()) - 1; i >= 0; --i) {
        reversed.push_back(s[i]);
    }
    s = std::move(reversed);
}
```

The output is correct, and the total time is O(n). However, the new array
holds `n` characters, so it needs O(n) extra space. Moving it afterward
does not remove that peak memory use. This version **does not satisfy
the O(1)-space requirement**; it is a starting point to improve.

## Optimal: swap from both ends

Keep `left` at the first character and `right` at the last. Swap their
characters, move both positions inward, and repeat. These are
[converging two pointers](/dsa/patterns/two-pointers).

```cpp
#include <utility>
#include <vector>

void reverseString(std::vector<char>& s) {
    int left = 0;
    int right = static_cast<int>(s.size()) - 1;
    while (left < right) {
        std::swap(s[left], s[right]);
        ++left;
        --right;
    }
}
```

For `hello`, first swap `h` and `o` to get `oellh`. Next swap `e` and the
second `l` to get `olleh`. Both pointers now reach the middle `l`, so stop.

After each swap, the two outer positions hold their final characters.
Later swaps touch only the remaining interior, so they cannot undo that
work. When the positions meet or cross, every pair has been handled.
Using `left < right` also avoids an unnecessary self-swap at an odd-length
array's center.

You can also use `std::reverse(s.begin(), s.end())` from `<algorithm>`.
Writing the loop yourself makes the pointer movement and space use clear.

## Complexity

Here `n` is the number of characters.

| Approach | Time | Extra space |
| --- | --- | --- |
| Copy backwards | O(n) | O(n) |
| Swap from both ends | O(n) | O(1) |

The pointer version makes `floor(n / 2)` swaps and keeps just two indices.
For arbitrary input, reversal needs linear work in the worst case, so its
O(n) time is optimal. The improvement over copying is in memory, not the
time class. This is why [complexity analysis](/dsa/patterns/asymptotic-analysis)
should include both time and extra space.
