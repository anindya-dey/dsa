## Problem

Write a function that reverses a string of characters in place: the
input array `s` is modified so that `s[i]` and `s[n - 1 - i]` swap.

**Constraints**

- `1 <= s.length <= 1000`
- `s[i]` is a printable ASCII character.

**Example**

```text
Input:  s = ["h","e","l","l","o"]
Output: ["o","l","l","e","h"]
```

## Brute force

Walk a second pointer from the end, building a new array.

```cpp
void reverseStringBrute(std::vector<char>& s) {
    std::vector<char> reversed;
    for (int i = static_cast<int>(s.size()) - 1; i >= 0; --i) {
        reversed.push_back(s[i]);         // walk backwards, copy
    }
    s = std::move(reversed);
}
```

O(n) time, O(n) extra space, and it works. Its "waste" is mild but
instructive for a first problem in the pattern: the reversal needs to
touch every element exactly once (which both versions do), and the
extra array exists only because the walk refuses to *pair* the
elements that must swap.

## The pattern: converging pointers

The reversal is symmetric: element i trades with element n - 1 - i, so
two pointers, one from each end, meet in the middle, swapping as they
go. This is the [converging shape](/dsa/patterns/two-pointers) in its
minimal form.

```cpp
void reverseString(std::vector<char>& s) {
    int left = 0;
    int right = static_cast<int>(s.size()) - 1;
    while (left < right) {
        std::swap(s[left], s[right]);
        ++left;
        --right;
    }
}
```

O(n) time, O(1) space, and n / 2 swaps. The loop condition
(`left < right`, not `<=`) is worth a sentence: when the pointers meet
or cross, they are pointing at the same element (odd length) or have
passed each other, and in both cases the remaining "pairs" are an
element with itself, so stopping there is both correct and required
(swapping past the middle would *un*-reverse the string).

This problem is the entry drug for the whole site's analysis habit:
both versions are O(n), and the *space* is where the improvement lives
(O(1) against O(n)), which makes it the cleanest possible illustration
of the asymptotic-analysis point that [complexity has two
axes](/dsa/patterns/asymptotic-analysis), and that "the same time
complexity" can still hide a real improvement. The in-place swap is
also the exact move that powers
[rotate array](/dsa/patterns/linear-structures/rotate-array)
(a triple reversal) and
[reverse linked list](/dsa/patterns/linked-list-manipulation/reverse-linked-list)
(the pointer-surgery version of the same idea).

## Complexity

| Approach | Time | Space |
| --- | --- | --- |
| Copy backwards | O(n) | O(n) |
| Converging pointers, in place | O(n) | O(1) |

Linear time is optimal (every element must move), so the pointer version
is the honest optimum: same time, minimal space, and the template for
every symmetric in-place transformation.
