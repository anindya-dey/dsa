## Problem

You are given points with integer coordinates, `points[i] = [x, y]`.
Visit them in the listed order, starting at the first point.

In one second, you can move one unit horizontally, one unit vertically,
or one unit along **both** axes diagonally. Return the minimum total time.
Passing through a later point does not count as visiting it before its turn.

**Constraints**

- `1 <= points.length <= 100`
- Each point has exactly two coordinates.
- `-1000 <= x, y <= 1000`

**Example**

```text
Input:  points = [[3, 2], [-2, 4]]
Output: 5
```

You need to travel 5 units horizontally and 2 vertically. Two diagonal
moves reach `(1, 4)`, then three horizontal moves reach `(-2, 4)`.
That takes five seconds.

## Brute force: simulate each second

Move one unit toward the target on each axis that has not reached it.
When both coordinates differ, this makes a diagonal move. When only one
differs, it makes a straight move.

```cpp
#include <cstddef>
#include <vector>

long long minTimeToVisitAllPointsBrute(
        const std::vector<std::vector<int>>& points) {
    long long total = 0;
    for (std::size_t i = 1; i < points.size(); ++i) {
        int x = points[i - 1][0];
        int y = points[i - 1][1];
        int targetX = points[i][0];
        int targetY = points[i][1];
        while (x != targetX || y != targetY) {
            x += (targetX > x) - (targetX < x);
            y += (targetY > y) - (targetY < y);
            ++total;
        }
    }
    return total;
}
```

Each comparison produces 0 or 1. Their difference is +1 when the target
is ahead, -1 when it is behind, and 0 when that coordinate already matches.
The simulation is correct, but it does one loop iteration per second
of travel. You can calculate the same answer without taking every step.

## Optimal: count the larger gap

Let `dx` and `dy` be the absolute horizontal and vertical gaps. Each
second closes at most one unit of either gap, so you need **at least
`max(dx, dy)` seconds**.

You can achieve that bound: take `min(dx, dy)` diagonal moves, then finish
the remaining gap with straight moves. For gaps 5 and 2, that is two
diagonals plus three straight moves, exactly five seconds.

Therefore each consecutive pair contributes `max(dx, dy)`. This is also
called **Chebyshev distance**. Add those contributions because you must
finish one leg before the next begins.

```cpp
#include <algorithm>
#include <cstddef>
#include <cstdlib>
#include <vector>

long long minTimeToVisitAllPoints(
        const std::vector<std::vector<int>>& points) {
    long long total = 0;
    for (std::size_t i = 1; i < points.size(); ++i) {
        long long dx = std::abs(
            static_cast<long long>(points[i][0]) - points[i - 1][0]);
        long long dy = std::abs(
            static_cast<long long>(points[i][1]) - points[i - 1][1]);
        total += std::max(dx, dy);
    }
    return total;
}
```

The problem's limits fit in a 32-bit `int`; `long long` also lets these
functions handle larger gaps. Convert before subtracting so the difference itself
cannot overflow `int`. With one point, there are no legs and the answer is 0.

## Complexity

Let `n` be the number of points and `S` the total number of simulated steps.

| Approach | Time | Extra space |
| --- | --- | --- |
| Simulate each second | O(n + S) | O(1) |
| Formula for each leg | O(n) | O(1) |

The coordinate bound makes simulation manageable here, but the formula
does constant work per leg regardless of the gap. This is an
[analysis](/dsa/patterns/asymptotic-analysis) lesson: count what actually
controls a loop, not just the number of input items.
