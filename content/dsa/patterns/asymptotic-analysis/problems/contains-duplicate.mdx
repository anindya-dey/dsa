## Problem

Given an integer array `nums`, return `true` if any value appears at least
twice. Return `false` if all values are distinct.

**Constraints**

- `1 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`

**Example**

```text
Input:  nums = [1, 2, 3, 1]
Output: true
```

The value 1 appears at indices 0 and 3. You only need to find one repeated
value, not list every duplicate.

## Brute force: compare every pair

For each element, check every later element. Starting `j` at `i + 1`
avoids comparing an element with itself or checking the same pair twice.

```cpp
#include <vector>

bool containsDuplicateBrute(const std::vector<int>& nums) {
    int n = static_cast<int>(nums.size());
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            if (nums[i] == nums[j]) {
                return true;
            }
        }
    }
    return false;
}
```

This uses O(1) extra space and stops as soon as a pair matches. With no
duplicates, it makes `n * (n - 1) / 2` comparisons. At 100,000 elements,
that is 4,999,950,000 comparisons, so the worst-case O(n²) time is too
expensive for a typical coding-problem time limit.

## Alternative: sort a copy

Sorting puts equal values next to each other. You then only need to
compare neighboring positions. The function takes `nums` by value so
sorting its copy does not change the caller's array.

```cpp
#include <algorithm>
#include <cstddef>
#include <vector>

bool containsDuplicateSort(std::vector<int> nums) {
    std::sort(nums.begin(), nums.end());
    for (std::size_t i = 1; i < nums.size(); ++i) {
        if (nums[i] == nums[i - 1]) {
            return true;
        }
    }
    return false;
}
```

For `[1, 2, 3, 1]`, the sorted copy is `[1, 1, 2, 3]`. The first neighbor
comparison finds the duplicate. Sorting costs O(n log n), and the copy
uses O(n) extra space. If changing the input is allowed, taking a
reference avoids the copy, but sorting may still use stack space.

## Optimal average time: use a hash set

A **hash set** stores each distinct value once. Before moving on, insert
the current value. If it was already present, you have found a duplicate.

```cpp
#include <unordered_set>
#include <vector>

bool containsDuplicate(const std::vector<int>& nums) {
    std::unordered_set<int> seen;
    for (int value : nums) {
        if (!seen.insert(value).second) {
            return true;
        }
    }
    return false;
}
```

`insert(value).second` is `true` when a new value was inserted and `false`
when it already existed. In the example, the set becomes `{1}`, then
`{1, 2}`, then `{1, 2, 3}`. Inserting the last 1 fails, so you return
`true`. If every insertion succeeds, all values are distinct.

This avoids rechecking earlier elements. Insertion is O(1) on average
when hashes distribute values well, giving O(n) average time overall.
Many values sharing a hash bucket cause **collisions**. These can make one
insertion O(n), and the entire scan O(n²) in the worst case. The set may
store all `n` values, so it uses O(n) space.

## Complexity and choice

Here `n` is the number of elements. Space includes the sorting copy.

| Approach | Time | Extra space |
| --- | --- | --- |
| Compare every pair | O(n²) worst case | O(1) |
| Sort a copy, then scan neighbors | O(n log n) worst case | O(n) for the copy |
| Hash set | O(n) average; O(n²) worst case | O(n) |

The hash set is a good default when memory is available. Sorting gives a
worst-case O(n log n) time bound without relying on hash distribution.
This [analysis](/dsa/patterns/asymptotic-analysis) example shows why you
should state time, extra space, and assumptions together.
