## Problem

Given an `m x n` matrix, if an element is 0, set its entire row and entire
column to 0. Do it **in place**, using O(1) extra space.

**Constraints**

- `1 <= m, n <= 200`
- `-2^31 <= matrix[i][j] <= 2^31 - 1`

**Example**

```text
Input:  matrix = [[0,1,2,0],
                  [3,4,5,2],
                  [1,3,1,5]]
Output: [[0,0,0,0],
         [0,4,5,0],
         [0,3,1,0]]
```

## Brute force

A first attempt that *looks* right: scan the matrix, and on each zero,
immediately zero its row and column.

```cpp
void setZeroesEager(std::vector<std::vector<int>>& matrix) {
    int m = static_cast<int>(matrix.size());
    int n = static_cast<int>(matrix[0].size());
    for (int i = 0; i < m; ++i) {
        for (int j = 0; j < n; ++j) {
            if (matrix[i][j] == 0) {                 // BUG: sees zeros we wrote
                for (int c = 0; c < n; ++c) {
                    matrix[i][c] = 0;
                }
                for (int r = 0; r < m; ++r) {
                    matrix[r][j] = 0;
                }
            }
        }
    }
}
```

This is wrong, and the reason is the entire problem. The zeros it writes
become evidence for later scans, cascading through the whole matrix.
The fix, using O(m + n) extra space, is to record the *original* zeros
first: one `shouldZero` flag per row and per column, then one sweep that
applies them.

```cpp
void setZeroesExtra(std::vector<std::vector<int>>& matrix) {
    int m = static_cast<int>(matrix.size());
    int n = static_cast<int>(matrix[0].size());
    std::vector<bool> rowZero(m, false), colZero(n, false);
    for (int i = 0; i < m; ++i) {
        for (int j = 0; j < n; ++j) {
            if (matrix[i][j] == 0) {
                rowZero[i] = true;                  // record, don't act yet
                colZero[j] = true;
            }
        }
    }
    for (int i = 0; i < m; ++i) {
        for (int j = 0; j < n; ++j) {
            if (rowZero[i] || colZero[j]) {
                matrix[i][j] = 0;
            }
        }
    }
}
```

Correct, O(m·n) time, O(m + n) space. The remaining question is what the
O(1) constraint costs.

## Optimal: the matrix stores its own flags

The two flag arrays exist to survive the "record now, act later" gap. But
the matrix has spare storage of its own: *row 0* and *column 0* can serve
as the flag arrays, as long as you handle one collision. The cell
`matrix[0][0]` would need to mean both "row 0 should be zeroed" and
"column 0 should be zeroed", so it can only carry one of the two.

```cpp
void setZeroes(std::vector<std::vector<int>>& matrix) {
    int m = static_cast<int>(matrix.size());
    int n = static_cast<int>(matrix[0].size());
    bool firstRowZero = false;
    bool firstColZero = false;

    for (int j = 0; j < n; ++j) {                   // does row 0 itself zero?
        if (matrix[0][j] == 0) {
            firstRowZero = true;
        }
    }
    for (int i = 0; i < m; ++i) {                   // does column 0 itself zero?
        if (matrix[i][0] == 0) {
            firstColZero = true;
        }
    }
    for (int i = 1; i < m; ++i) {                   // record into row0/col0
        for (int j = 1; j < n; ++j) {
            if (matrix[i][j] == 0) {
                matrix[i][0] = 0;                  // flags: column j
                matrix[0][j] = 0;                  // flags: row i
            }
        }
    }
    for (int i = 1; i < m; ++i) {                   // apply interior flags
        for (int j = 1; j < n; ++j) {
            if (matrix[i][0] == 0 || matrix[0][j] == 0) {
                matrix[i][j] = 0;
            }
        }
    }
    if (firstRowZero) {                            // apply the two saved flags
        for (int j = 0; j < n; ++j) {
            matrix[0][j] = 0;
        }
    }
    if (firstColZero) {
        for (int i = 0; i < m; ++i) {
            matrix[i][0] = 0;
        }
    }
}
```

Read the two booleans as "the flag storage itself was compromised": row 0
and column 0 are being zeroed by the rules, so their own original state
must be saved *before* they are used as flags. That, plus doing the
interior application before the border application (so the flags survive
until the end), is the whole dance.

## Complexity

| Approach | Time | Space |
| --- | --- | --- |
| Eager zeroing | wrong | - |
| Flag arrays | O(m·n) | O(m + n) |
| Row/col 0 as flags | O(m·n) | O(1) |

The eager version's bug is the real teaching point: **an in-place
transform must not consume its own output as evidence**. Everything after
that bug (flags, then flags-in-place) is just progressively cleverer storage
for the same "record, then act" discipline. It is the trickiest in-place
transform in [Matrix & Grid Algorithms](/dsa/patterns/matrix-and-grid-algorithms).
