## Problem

Row 1 of a grammar is `0`. Each subsequent row replaces every 0 with
`01` and every 1 with `10`. Given row number `n` (1-indexed) and
position `k` (1-indexed within that row), return the k-th symbol in row
n. Rows double in length each time.

**Constraints**

- `1 <= n <= 30`
- `1 <= k <= 2^(n - 1)`

**Example**

```text
Row 1: 0
Row 2: 01
Row 3: 0110
Row 4: 01101001

Input:  n = 4, k = 5
Output: 1
```

## Brute force

Build the rows: each row is the previous row with every symbol expanded,
so generate row n explicitly (length 2^(n-1)) and index into it.

```cpp
int kthGrammarBrute(int n, int k) {
    std::string row = "0";
    for (int i = 1; i < n; ++i) {
        std::string next;
        for (char c : row) {
            next += (c == '0') ? "01" : "10";
        }
        row = std::move(next);
    }
    return row[k - 1] - '0';
}
```

O(2^n) time and memory: row 30 is half a billion symbols, for a problem
whose answer depends on exactly one path through that structure. The
built rows are the *entire* grammar, when the question asks about one
cell's ancestry.

## Optimal: recurse on the parent cell

The observation that shrinks the problem: every cell in row n was
generated by a specific cell in row n - 1. Cell k of row n comes from
cell `(k + 1) / 2` (integer division) of the row above, because each
parent produces exactly two children: positions 2p - 1 and 2p of the
next row.

So instead of building rows, walk *up* the ancestry: the k-th cell of row
n is the k-th cell's parent's value, transformed. And the transformation
rule is small enough to derive on the spot: a 0 parent writes `01`
(children 0 then 1), a 1 parent writes `10` (children 1 then 0). The
first child equals the parent; the second child is the parent flipped.
So:

- k odd (first child): the cell *equals its parent*.
- k even (second child): the cell is its parent *flipped*.

```cpp
int kthGrammar(int n, int k) {
    if (n == 1) {
        return 0;                           // base: the single seed cell
    }
    int parent = kthGrammar(n - 1, (k + 1) / 2);   // trust the ancestry
    if (k % 2 == 1) {
        return parent;                      // first child: same value
    }
    return 1 - parent;                     // second child: flipped
}
```

Each call shrinks *both* arguments strictly (n by one, k by half),
guaranteed to reach the base case `n = 1`, which is the seed `0`. The
recursion is n deep, not 2^n wide, and it visits exactly the ancestors
of the asked-about cell: the length of one root-to-cell path.

The derivation skill this problem is a test of: the rule "k-th cell
comes from cell (k + 1) / 2" is not given in the statement, it has to be
derived by noticing each parent contributes exactly two children. That
is the [recursion](/dsa/patterns/recursion-and-math) contract in
practice: define the step *from* the smaller problem (the parent), and
the base case (row 1) is stated by the grammar itself.

The parity flip (`1 - parent`) is also worth a second look, because it
is the *entire* accumulated state: walking up the ancestry, the answer is
the seed 0 flipped once for every even-position ancestor. That reading
gives the O(1) closed form (`1` minus... a parity-of-parities count), but
the recursive form is the one you can re-derive under pressure, which is
why it is the answer to give.

## Complexity

| Approach | Time | Space |
| --- | --- | --- |
| Build every row | O(2^n) time and memory | O(2^n) |
| Ancestry recursion | O(n) | O(n) stack |

The gap (exponential versus linear) is the general
[recursion](/dsa/patterns/recursion-and-math) lesson at its purest: the
grammar *defines* a 2^n structure, but a question about one location only
needs the one path that produced it, and recursing on the smaller
question (parent) instead of the smaller *structure* (row) is what selects
the path.
