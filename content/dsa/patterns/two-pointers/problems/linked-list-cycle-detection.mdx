## Problem

Given the `head` of a singly linked list, decide whether the list contains a
cycle. A cycle means some node's `next` pointer eventually leads back to a
node you've already visited, so walking forward never reaches `nullptr`.

**Constraints**

- The list may be empty.
- Don't modify the list.
- Avoid extra memory proportional to the number of nodes if you can.

## Brute force

Walk the list and remember every node you pass in a hash set. If you ever
arrive at a node that's already in the set, there's a cycle. If you reach
`nullptr`, there isn't.

```cpp
bool hasCycleBruteForce(Node* head) {
    std::unordered_set<Node*> visited;
    Node* current = head;

    while (current != nullptr) {
        if (visited.count(current)) {
            return true;
        }
        visited.insert(current);
        current = current->next;
    }

    return false;
}
```

This is O(n) time, which is fine, but it costs O(n) extra space. The set
grows with the list, and for a long list that's a lot of memory spent just
to answer a yes-or-no question.

## Optimal: fast & slow pointers (Floyd's cycle detection)

Think of a tortoise and a hare running around a track. The hare runs twice
as fast. If the track is a straight line, the hare reaches the finish first.
If the track loops, the hare keeps lapping and will eventually run into the
tortoise from behind.

We do exactly that. `slow` moves one node per step, `fast` moves two:

```cpp
bool hasCycle(Node* head) {
    Node* slow = head;
    Node* fast = head;

    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;
        fast = fast->next->next;

        if (slow == fast) {
            return true;
        }
    }

    return false;
}
```

If there's no cycle, `fast` hits `nullptr` and we return false. If there is
one, both pointers end up inside the loop. Once they're both in the cycle,
`fast` gains one position on `slow` every step, so the gap between them
shrinks by exactly one each time. A gap that shrinks by one can only reach
zero, never jump over it, which is why they're guaranteed to meet rather
than pass each other.

## Complexity

| Approach | Time | Space |
| --- | --- | --- |
| Hash set of visited nodes | O(n) | O(n) |
| Fast & slow pointers | O(n) | O(1) |

Floyd's algorithm keeps the same O(n) time and drops the extra memory
entirely, which is why it's the expected answer in interviews. It is the
fast-and-slow shape of [Two Pointers](/dsa/patterns/two-pointers).
