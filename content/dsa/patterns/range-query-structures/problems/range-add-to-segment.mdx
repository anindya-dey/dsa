## Problem

Implement an array supporting two operations on ranges:
`update(l, r, x)` adds `x` to every element in the inclusive range
`[l, r]`, and `query(l, r)` returns the sum of the range. Both
operations must run in O(log n).

**Constraints**

- `1 <= n <= 10^5`
- Up to 10^5 operations, in any interleaving.

**Example**

```text
init: nums = [1, 2, 3, 4, 5]
update(1, 3, 2)      // nums = [1, 4, 5, 6, 5]
query(1, 3)          -> 15 (4 + 5 + 6)
update(0, 4, 1)      // nums = [2, 5, 6, 7, 6]
query(0, 1)          -> 7
```

## Brute force

Update loops the range; query loops the range.

```cpp
class RangeAddBrute {
public:
    explicit RangeAddBrute(const std::vector<long long>& nums)
        : values_(nums) {}

    void update(int l, int r, long long x) {
        for (int i = l; i <= r; ++i) {     // touch every element
            values_[i] += x;
        }
    }

    long long query(int l, int r) const {
        long long sum = 0;
        for (int i = l; i <= r; ++i) {
            sum += values_[i];
        }
        return sum;
    }

private:
    std::vector<long long> values_;
};
```

O(n) per operation, O(n * q) total: hopeless at the limits. Note what
the problem *is not*: a
[prefix-sum](/dsa/patterns/prefix-sums-and-difference-arrays) array
would answer the queries in O(1) but dies on the updates (O(n) per
update to rebuild), and a plain difference array handles the range
*adds* in O(1) but dies on the queries (O(n) per read). The operations
interleave, so both halves must be fast, which is exactly the
[range-query structures](/dsa/patterns/range-query-structures)
condition that rules out both simple structures.

## Optimal: segment tree with lazy propagation

The base: a [segment tree](/dsa/patterns/range-query-structures) over
sums, each node holding the sum of its range, updates propagating
from leaf to root. The new requirement is the **range** update, and
the insight that makes it O(log n): **do not touch descendants you do
not need yet.** When an update fully covers a node's range, record the
addition *at the node* ("this whole subtree is +x bigger"), update the
node's stored sum (the update's effect on this node's aggregate is
computable: `add * rangeLength`), and *stop descending*. The
children's values are stale, and the record of that staleness is the
**lazy tag**.

```cpp
class LazySegmentTree {
public:
    explicit LazySegmentTree(const std::vector<long long>& nums)
        : n_(static_cast<int>(nums.size())),
          tree_(4 * std::max<size_t>(1, nums.size()), 0),
          lazy_(4 * std::max<size_t>(1, nums.size()), 0) {
        build(nums, 1, 0, n_ - 1);
    }

    void update(int l, int r, long long add) {
        update(1, 0, n_ - 1, l, r, add);
    }

    long long query(int l, int r) {
        return query(1, 0, n_ - 1, l, r);
    }

private:
    void build(const std::vector<long long>& nums,
               int node, int lo, int hi) {
        if (lo == hi) {
            tree_[node] = nums[lo];
            return;
        }
        int mid = lo + (hi - lo) / 2;
        build(nums, 2 * node, lo, mid);
        build(nums, 2 * node + 1, mid + 1, hi);
        tree_[node] = tree_[2 * node] + tree_[2 * node + 1];
    }

    void push(int node, int lo, int mid, int hi) {
        if (lazy_[node] != 0) {                 // deferred add sitting here
            apply(2 * node, lo, mid, lazy_[node]);
            apply(2 * node + 1, mid + 1, hi, lazy_[node]);
            lazy_[node] = 0;                     // the debt is paid downward
        }
    }

    void apply(int node, int lo, int hi, long long add) {
        tree_[node] += add * (hi - lo + 1);     // effect on this node's sum
        lazy_[node] += add;                      // and remember it for children
    }

    void update(int node, int lo, int hi, int l, int r, long long add) {
        if (r < lo || hi < l) {
            return;                              // no overlap
        }
        if (l <= lo && hi <= r) {                 // fully covered: stop here
            apply(node, lo, hi, add);
            return;
        }
        push(node, lo, lo + (hi - lo) / 2, hi);   // partial: settle debts first
        int mid = lo + (hi - lo) / 2;
        update(2 * node, lo, mid, l, r, add);
        update(2 * node + 1, mid + 1, hi, l, r, add);
        tree_[node] = tree_[2 * node] + tree_[2 * node + 1];
    }

    long long query(int node, int lo, int hi, int l, int r) {
        if (r < lo || hi < l) {
            return 0;
        }
        if (l <= lo && hi <= r) {                 // fully covered: this node's answer
            return tree_[node];
        }
        push(node, lo, lo + (hi - lo) / 2, hi);   // partial: children must be honest
        int mid = lo + (hi - lo) / 2;
        return query(2 * node, lo, mid, l, r)
             + query(2 * node + 1, mid + 1, hi, l, r);
    }

    int n_;
    std::vector<long long> tree_;
    std::vector<long long> lazy_;
};
```

The lazy machinery is three moves, and each earns its line:

- **`apply`** computes the update's effect on a *node* without
  descending: the sum changes by `add * length`, and the tag
  accumulates so children can catch up later.
- **The fully-covered early return** is the entire speedup: a range
  update touches O(log n) nodes (the ones tiling the range) instead of
  O(range length) leaves, because covering *a node's whole range*
  covers all its descendants implicitly.
- **`push`** pays the deferred debt *downward, one level, just before
  descending*: the moment anything needs a child (a partial update, a
  query), the child's value must be true, so the parent hands its tag
  down and clears it. Tags otherwise sit indefinitely, which is the
  "lazy": correctness never requires eager descent, only *descendable*
  honesty.

The invariant worth stating: a node's `tree_` value is **always
correct as its own sum** (apply updates it immediately), and only its
*children's* values may be stale, by exactly the amount in `lazy_`.
Queries and partial updates push before descending, so no stale value
is ever read. Every bug in lazy propagation is a missing push, and
reciting the invariant ("my sum is true, my children may be behind by
my tag, push before trusting them") is the debugging discipline.

## Complexity

| Approach | update | query | Space |
| --- | --- | --- | --- |
| Loop the range | O(n) | O(n) | O(n) |
| Lazy segment tree | **O(log n)** | **O(log n)** | O(4n) |

Each operation touches O(log n) nodes (the tiling of the query range,
plus the path down), with O(1) work per node. This is the canonical
range-update problem of
[range-query structures](/dsa/patterns/range-query-structures), the
step past the point-update
[Fenwick](/dsa/patterns/range-query-structures/range-sum-query-mutable)
(the Fenwick can be extended to range updates with two BITs, a
cleverness worth knowing exists but a trickier one), and the standard
interview-grade demonstration of lazy propagation: the deferred-
update idea that keeps interleaved range operations logarithmic.
