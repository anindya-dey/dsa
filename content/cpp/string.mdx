An ordinary C-style string is read until a zero character marks its end.
`std::string` owns its characters and records their length separately, so
it can grow, copy its text, and report its size without scanning for that
marker. Use it when your program needs to keep and modify text.

## Characters, length, and access

The characters occupy contiguous storage. A **NUL terminator**, the zero
character written as `'\0'`, follows the stored text. It is not included
in `size()`. C APIs expecting NUL-terminated text can read the characters
through the pointer returned by `c_str()`.
`size()` and `length()` return the same count in O(1). For UTF-8 text, this
is a byte count, not necessarily the number of characters you see on screen.
Strings can also contain embedded zero characters: `size()` counts them,
but an API expecting NUL-terminated text stops at the first zero.

```cpp
#include <cassert>
#include <string>
#include <string_view>

int main() {
    std::string message = "hello";
    message += "!";

    assert(message.size() == 6);
    assert(message.at(0) == 'h');
    assert(message.substr(1, 3) == "ell");
    assert(message.find("ll") == 2);
    assert(message[message.size()] == '\0');
}
```

`substr(1, 3)` copies three characters starting at index 1. `find` returns
the first matching position, or `std::string::npos`, a special value meaning
"not found". Check for `npos` before using the result as an index.

`message[i]` is unchecked, while `message.at(i)` throws `std::out_of_range`
when `i` is not an element index. You may read `message[message.size()]`
to inspect the terminator, but `at(size())` throws. Access beyond the
terminator, or changing it to a nonzero character, is undefined behavior
in C++20.

Equality compares the stored text. Ordering is **lexicographic**: compare
the first differing characters, with a shorter matching prefix coming
first. This follows character-code order, not language-aware dictionary order.

## Copies, views, and function arguments

Calling `substr` on a named string makes a separate owned copy. A `std::string_view`
(C++17) instead refers to existing characters without owning them. That
saves copying, but also means it observes changes to those characters:

```cpp
std::string original = "hello";
std::string copy = original.substr(1, 3);
std::string_view view = std::string_view{original}.substr(1, 3);

original[1] = 'a';
assert(copy == "ell");
assert(view == "all");
```

Keep the source alive while using a view, and do not use the view after an
operation invalidates its storage. A view also need not end at a NUL
terminator, so its `data()` is not automatically a C-style string.

For a function that only reads an existing string, `const std::string&`
avoids copying it. A by-value `std::string` parameter owns its own text;
passing an existing string normally copies it, while a temporary or an
explicitly moved argument can avoid a copy. Choose according to whether
the function needs to borrow the text or own it.

Common libraries use **small-string optimization**: short text fits inside
the string object without a separate allocation. The size threshold is
implementation-dependent. A short substring still copies characters even
when that copy needs no heap allocation; an ordinary string move may
transfer a large allocation, but moving a short string usually copies its
inline characters.

## Building text and keeping pointers valid

`a + b` creates a result string; `a += b` appends to `a`. Repeatedly
rebuilding a growing result with `+` can take O(n²) copying. Prefer
appending, and use `reserve` when you know the expected final size.
Insertion and erasure can shift the remaining characters; replacing text
also copies the replacement, so these operations can be linear in the
amount of text affected.

`c_str()` returns a pointer into the string's NUL-terminated storage.
It is not a separate copy. Destruction makes that pointer unusable, and
operations such as appending or assignment may invalidate it. Obtain a
fresh pointer after such changes. Writing an existing character through
`s[i]` changes the text without invalidating the pointer.

Never save a pointer from a temporary such as `(a + b).c_str()`: the
temporary normally dies at the statement's semicolon. String invalidation
rules are not identical to vector's, so do not assume that avoiding
reallocation preserves every saved handle.

## Parsing and formatting text

`std::stoi` converts an integer prefix. It throws `std::invalid_argument`
if no number can be read, and `std::out_of_range` if the result cannot fit
in an `int`. It accepts leading whitespace and an optional sign. Trailing
text does not automatically cause an exception:

```cpp
std::string input = "42x";
std::size_t used = 0;
int value = std::stoi(input, &used);
assert(value == 42 && used == 2);
```

For a whole-string integer, also require `used == input.size()`.
`std::to_string` formats a number. `std::getline` reads up to a chosen
delimiter without storing that delimiter, while `std::format` (C++20)
builds formatted text.
