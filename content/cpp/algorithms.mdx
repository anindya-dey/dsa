The sorting tools live in `<algorithm>`. Each takes a range as two
iterators, usually `v.begin()` and `v.end()`, and works on any
random-access sequence: vectors, strings, deques, and `std::array`.

## Sorting

```cpp
#include <algorithm>
#include <cassert>
#include <functional>
#include <vector>

int main() {
    std::vector<int> v = {5, 2, 9, 1};
    std::sort(v.begin(), v.end());
    assert((v == std::vector<int>{1, 2, 5, 9}));

    std::sort(v.begin(), v.end(), std::greater<int>());
    assert((v == std::vector<int>{9, 5, 2, 1}));

    std::vector<std::vector<int>> intervals = {{3, 4}, {1, 5}, {2, 2}};
    std::sort(intervals.begin(), intervals.end(),
              [](const std::vector<int>& a, const std::vector<int>& b) {
                  return a[1] < b[1];  // By end point.
              });
    assert(intervals[0][1] == 2 && intervals[2][1] == 5);
}
```

`std::sort` takes O(n log n) comparisons. Without a comparator it sorts
ascending using `<`. With `std::greater<int>()` it sorts descending. A
lambda comparator returns `true` when `a` should come before `b`, and must
use a strict test such as `<`, never `<=`.

`std::sort` is **not stable**: elements that compare equal may end up in
any order. If ties must keep their original order, use
`std::stable_sort`, which is also O(n log n) when extra memory is
available. Often a tie-breaker in the comparator is simpler.

## Selecting without a full sort

```cpp
std::vector<int> v = {7, 3, 9, 1, 5};
std::nth_element(v.begin(), v.begin() + 2, v.end());
assert(v[2] == 5);  // The element a full sort would put at index 2.

std::vector<int> w = {7, 3, 9, 1, 5};
std::partial_sort(w.begin(), w.begin() + 2, w.end());
assert(w[0] == 1 && w[1] == 3);  // The 2 smallest, in order.
```

`std::nth_element(begin, begin + k, end)` puts the element that belongs at
index k there, with nothing larger before it and nothing smaller after.
The two sides are otherwise unsorted. It runs in O(n) on average, which
makes it the quick way to find the kth smallest value or a median.

`std::partial_sort(begin, begin + k, end)` sorts only the first k
positions, giving the k smallest values in order in O(n log k).

## Everyday helpers

```cpp
std::vector<int> v = {3, 1, 3, 2, 1};
assert(*std::min_element(v.begin(), v.end()) == 1);
assert(*std::max_element(v.begin(), v.end()) == 3);
assert(std::max_element(v.begin(), v.end()) - v.begin() == 0);  // Index.

std::sort(v.begin(), v.end());                       // {1, 1, 2, 3, 3}
v.erase(std::unique(v.begin(), v.end()), v.end());   // {1, 2, 3}
std::reverse(v.begin(), v.end());                    // {3, 2, 1}
assert((v == std::vector<int>{3, 2, 1}));
```

`min_element` and `max_element` return an iterator to the first smallest
or largest element in O(n). Dereference it for the value, or subtract
`v.begin()` for the index. You never need to sort just to find a minimum.
Both need a nonempty range before you dereference.

`std::unique` removes only **adjacent** duplicates, so sort first. It does
not shrink the vector; it returns where the kept elements end, and `erase`
removes the leftovers. `std::reverse` reverses in place, and
`std::rotate(v.begin(), v.begin() + k, v.end())` moves the first k
elements to the end.
