---
title: "Integer Overflow & Limits"
summary: "Where int runs out, why signed overflow is undefined, and the habits that prevent it."
---

An `int` holds roughly ±2.1 × 10^9. Problems routinely give 10^5 values of
up to 10^9 each, so a single sum or product can pass that limit. For
signed integers, going past the limit is **undefined behavior**. The
compiler may assume it never happens, so you cannot rely on the value
wrapping around.

## The limits

| Type | Largest value | Roughly |
| --- | --- | --- |
| `int` | 2,147,483,647 (`INT_MAX`) | 2.1 × 10^9 |
| `long long` | 9,223,372,036,854,775,807 (`LLONG_MAX`) | 9.2 × 10^18 |

`INT_MAX` and `LLONG_MAX` come from `<climits>`; the same values are
available as `std::numeric_limits<int>::max()` from `<limits>`. The
smallest `int`, `INT_MIN`, is -2,147,483,648: one further from zero than
`INT_MAX`. That is why `-INT_MIN` and `std::abs(INT_MIN)` overflow, the
trap in [Pow(x, n)](/dsa/patterns/recursion-and-math/pow-x-n-recursive).

## Where overflow hides

```cpp
#include <cassert>
#include <numeric>
#include <vector>

int main() {
    std::vector<int> nums(100000, 1000000000);  // 10^5 values of 10^9.

    long long total = 0;
    for (int x : nums) total += x;               // Each x widens: safe.
    assert(total == 100000000000000LL);

    assert(std::accumulate(nums.begin(), nums.end(), 0LL) == total);

    int width = 100000, height = 100000;
    long long area = 1LL * width * height;       // Widen first: safe.
    assert(area == 10000000000LL);
    // int bad = width * height;                 // Multiplies in int: overflow.

    int lo = 2000000000, hi = 2100000000;
    int mid = lo + (hi - lo) / 2;                // (lo + hi) / 2 overflows.
    assert(mid == 2050000000);
}
```

- **Sums of many values.** Keep the total in a `long long`. With
  `std::accumulate`, pass `0LL` as the start value, because `0` sums in `int`.
- **Products.** Widen *before* multiplying: `1LL * a * b`. Writing
  `(long long)(a * b)` is too late, because the multiplication has already
  overflowed in `int`.
- **Midpoints.** `(lo + hi) / 2` overflows when both are large. Write
  `lo + (hi - lo) / 2`.
- **"Infinity" sentinels.** `INT_MAX + w` overflows in a shortest-path
  update. Check `dist != INT_MAX` before adding.

## Modular arithmetic

When a problem says "return the answer modulo 10^9 + 7", reduce after
every addition and multiplication. Each value then stays below the
modulus, and a product of two of them stays below about 10^18, inside
`long long`:

```cpp
const long long MOD = 1'000'000'007;
long long a = 123456789, b = 987654321;
long long product = (a % MOD) * (b % MOD) % MOD;
long long diff = ((a - b) % MOD + MOD) % MOD;  // Never negative.
assert(product >= 0 && product < MOD && diff >= 0);
```

In C++, `%` of a negative number is negative: `-3 % 5` is `-3`. After a
subtraction, add `MOD` and reduce again, as in `diff` above.

## Unsigned is not a fix

Unsigned arithmetic wraps around in a defined way, but that only swaps
undefined behavior for silent wrong answers. `v.size()` is unsigned, so
`v.size() - 1` is a huge number when `v` is empty. Compare
`i + 1 < v.size()` instead, or convert the size to `int` before subtracting.

## Catching it

Compile with `-fsanitize=undefined` while testing. It reports signed
overflow at the exact line where it happens.
