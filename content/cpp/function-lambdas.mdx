A **lambda** is a small unnamed function you write right where you need
it. Most DSA code uses lambdas as sort comparators, as conditions for
algorithms such as `std::count_if`, and as recursive helpers like a
depth-first search.

## Writing a lambda

```cpp
#include <algorithm>
#include <cassert>
#include <vector>

int main() {
    auto add = [](int a, int b) { return a + b; };
    assert(add(2, 3) == 5);

    std::vector<int> v = {5, 1, 8, 3};
    int limit = 4;
    auto big = std::count_if(v.begin(), v.end(),
                             [limit](int x) { return x > limit; });
    assert(big == 2);

    std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });
    assert((v == std::vector<int>{8, 5, 3, 1}));
}
```

The parts are `[captures](parameters) { body }`. The return type is
usually deduced from the `return` statement. Store a lambda in an `auto`
variable, or pass it straight to a function.

## Captures

The square brackets list the outside variables the lambda may use:

- `[limit]` copies `limit` into the lambda when it is created. Later
  changes to `limit` do not affect the copy.
- `[&total]` refers to the original `total`, so the lambda can read its
  current value and change it.
- `[=]` copies every outside variable the body uses; `[&]` refers to all
  of them. `[&]` is the common choice inside a single function.
- `[]` captures nothing.

```cpp
int total = 0;
std::vector<int> nums = {1, 2, 3};
std::for_each(nums.begin(), nums.end(), [&total](int x) { total += x; });
assert(total == 6);
```

A lambda that captures by reference must not be used after those
variables are gone, for example after the function that created them
returns. Inside one solution function this rarely matters.

## Recursive helpers with std::function

`auto dfs = [&](int u) { ... dfs(next); }` does not compile: an `auto`
variable cannot appear in its own initializer, because its type is not
known yet. Declaring it as a `std::function` from `<functional>` gives it
a type up front:

```cpp
std::vector<std::vector<int>> adj = {{1, 2}, {3}, {}, {}};
std::vector<bool> seen(adj.size(), false);
int visited = 0;

std::function<void(int)> dfs = [&](int u) {
    seen[u] = true;
    ++visited;
    for (int next : adj[u]) {
        if (!seen[next]) dfs(next);
    }
};
dfs(0);
assert(visited == 4);
```

`std::function<void(int)>` means "a callable that takes an `int` and
returns nothing". It can hold any lambda or function with that shape. It
adds a little call overhead compared with `auto`, which is rarely
noticeable. A plain member function in the solution class also works.

## Lambdas as comparators

A sort comparator returns `true` when `a` should come before `b`. A heap,
set, or map also needs the comparator's type as a template argument.
`decltype(cmp)` names that type, and passing `cmp` to the constructor
hands over the lambda itself:

```cpp
auto cmp = [](const std::pair<int, int>& a, const std::pair<int, int>& b) {
    return a.second > b.second;  // Smaller second on top.
};
std::priority_queue<std::pair<int, int>, std::vector<std::pair<int, int>>,
                    decltype(cmp)> heap(cmp);
heap.push({1, 9});
heap.push({2, 4});
assert(heap.top().first == 2);
```

Comparators must use a strict test such as `<` or `>`, never `<=` or `>=`.
