Lambdas are this site's most-used C++ feature after the containers
themselves: every custom comparator, every hash, every
[greedy sort key](/dsa/patterns/greedy-algorithms/partition-labels),
every strategy parameter is a lambda. This entry covers the
mechanics (capture, the type rules) and the
[comparator pattern](#the-comparator-pattern) that everything else
depends on.

## The syntax, fully unpacked

```cpp
[captures] (params) -> returnType { body }
//        ^ optional         ^ almost always omitted (deduced)

auto add = [](int a, int b) { return a + b; };

int threshold = 10;
auto over = [threshold](int x) { return x > threshold; };   // BY VALUE: copied in
auto bump = [&threshold](int x) { return x > threshold++; };// BY REF: sees updates
auto copyAll = [=](int x) { ... };                          // capture all used, by value
auto refAll = [&](int x) { ... };                           // capture all used, by reference
auto moveIn = [v = std::move(bigVector)](int x) { ... };     // init-capture: MOVE in (C++14)
```

The capture rules are the trap surface:

- **`[=]` / `[&]` capture everything *used***, the convenient
  default that hides what a closure depends on (and `[&]`'s
  dangling risk: see below).
- **`[&]` closure outliving the captured variable** is the classic
  bug: a lambda capturing locals by reference, stored past the
  enclosing scope's return (a
  [callback](/system-design/lld/pubsub-broker-lld) stored in a
  subscription, a [comparator](#the-comparator-pattern) holding
  state), reading freed memory. The rule: **by-reference captures
  must not outlive the captured thing**; by-value captures are safe
  but copy.
- **`mutable`** lets a by-value capture *modify its copy* (rarely
  needed, occasionally exactly right).

## std::function: the type-erased callable

A lambda's *type is unique and unnamed* (you cannot write it), so
passing one around needs either `auto` (templates: the common
case) or `std::function<R(Args...)>`, the **type-erased**
callable: any callable with a matching signature, stored in one
type, callable through it.

```cpp
std::function<bool(int)> predicate = over;         // store a lambda
predicate = [](int x) { return x < 0; };           // reassign: a DIFFERENT lambda
bool ok = predicate(42);                          // call through the type

void each(std::function<void(int)> handler);       // the [broker](/system-design/lld/pubsub-broker-lld) signature
```

The trade: `std::function` costs (indirection, a possible heap
allocation for large captures, no inlining) where `auto`/template
parameters cost nothing, so the rule is **templates for
performance paths, `std::function` where storage or a fixed
signature is required** (a [member](/system-design/lld/task-scheduler-lld)
holding a handler, a container of callbacks: the places the type
*must* be nameable).

## The comparator pattern

The single most-used form on this site, a lambda as a sort or
heap comparator, capturing whatever state it needs:

```cpp
// Sort by (second, then first): DESCENDING second, ties ascending first.
std::sort(items.begin(), items.end(),
          [](const Item& a, const Item& b) {
              if (a.second != b.second) return a.second > b.second;   // desc
              return a.first < b.first;                              // tiebreak asc
          });

// A heap of (priority, payload), MIN-heap by priority:
auto cmp = [](const std::pair<int,std::string>& a,
              const std::pair<int,std::string>& b) {
    return a.first > b.first;         // ">" : MIN-heap ([the trick](/cpp/priority-queue))
};
std::priority_queue<std::pair<int,std::string>,
                    std::vector<std::pair<int,std::string>>,
                    decltype(cmp)> queue(cmp);    // decltype: the unnamed type
                                            // ^ pass the lambda IN: it has state
```

Two details make this pattern correct every time:

- **The comparator is a *strict weak ordering*** ("less than", not
  "less or equal"): return `true` iff `a` goes *before* `b`, and
  equal elements return `false` *both ways*: returning `true`
  for equal elements (the `<=` mistake) is
  **undefined behavior** in `std::sort` (the comparator
  contradicting itself mid-sort: the classic crash inside
  `std::__sort`).
- **`decltype(cmp)` + passing `cmp` in**: the heap *stores* the
  comparator (it must be
  [default-constructible-or-passed](https://en.cppreference.com/w/cpp/container/priority_queue/priority_queue)),
  which is why the [Dijkstra](/dsa/patterns/graph-specializations/network-delay-time)
  and [merge-k](/dsa/patterns/heaps-and-priority-queues/merge-k-sorted-lists)
  solutions on this site construct with the lambda as an argument.
