---
title: "Iterator Invalidation"
summary: "When saved iterators and references stop working, and how to erase safely while looping."
---

An iterator, pointer, or reference that you saved can stop working after
the container changes. Using it afterwards is **invalidated** access:
undefined behavior that may crash, return stale data, or seem fine on
small tests. This page lists when that happens and the safe patterns.

## The rules by container

| Container | After an insert | After an erase |
| --- | --- | --- |
| `vector` | If it reallocated: everything. Otherwise: positions at or after the insert, and `end()` | Positions at or after the erased element, and `end()` |
| `string` | Treat everything as invalid after any change in length | Same |
| `deque` | At either end: all iterators, but references stay valid. In the middle: everything | At either end: only the erased element (and `end()` when the last element goes). In the middle: everything |
| `map`, `set`, `list` | Nothing | Only the erased element |
| `unordered_map`, `unordered_set` | Nothing, unless it rehashed: then all iterators, while references stay valid | Only the erased element |

A vector reallocates whenever an insert needs more than its current
capacity, and you rarely know when that is. So in practice: **after any
`push_back` or `insert` on a vector, assume every saved position is gone.**

## A classic bug

```cpp
std::vector<int> v = {1, 2, 3};
int& first = v[0];
v.push_back(4);   // May reallocate.
// first may now refer to freed memory. Do not use it.
```

Save the index `0` instead of a reference, and read `v[0]` again after the
change. Indices stay meaningful in a vector as long as you only add at the
end.

## Erasing while looping

Erasing inside a range-based `for` over the same container breaks the
loop. Use an iterator loop and take the iterator that `erase` returns,
which points to the next element:

```cpp
#include <cassert>
#include <map>
#include <vector>

int main() {
    std::vector<int> v = {1, 2, 3, 4, 5};
    for (auto it = v.begin(); it != v.end();) {
        if (*it % 2 == 0) {
            it = v.erase(it);  // Continue from the next element.
        } else {
            ++it;
        }
    }
    assert((v == std::vector<int>{1, 3, 5}));

    std::map<int, int> m = {{1, 10}, {2, 20}, {3, 30}};
    for (auto it = m.begin(); it != m.end();) {
        if (it->second > 15) it = m.erase(it);
        else ++it;
    }
    assert(m.size() == 1);

    std::vector<int> w = {1, 2, 3, 4};
    std::erase_if(w, [](int x) { return x % 2 == 0; });  // C++20.
    assert((w == std::vector<int>{1, 3}));
}
```

The same loop works for `map`, `set`, and the unordered containers. For a
vector, each `erase` shifts the rest of the elements, so erasing many in a
loop costs O(n²). `std::erase_if(v, pred)` (C++20) removes every match in
one O(n) pass. Before C++20 the same job was written as
`v.erase(std::remove_if(v.begin(), v.end(), pred), v.end())`.

## Rules of thumb

- Do not add to or remove from a container inside a range-based `for`
  over that same container.
- Save indices into a vector, not iterators or references, if it may grow.
- When erasing in a loop, always continue from the iterator `erase` returns.
- When you need stable references across inserts, a `map`, `set`, or
  `list` keeps every element in place.
