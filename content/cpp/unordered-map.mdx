`std::unordered_map` stores one value for each unique key, such as a count
for each word. `std::unordered_set` stores unique keys with no values, so
it answers "have I seen this?" Both use hashing, which makes lookup,
insertion, and erasure O(1) on average.

## Counting and looking up

```cpp
#include <cassert>
#include <string>
#include <unordered_map>
#include <unordered_set>

int main() {
    std::unordered_map<std::string, int> counts;
    for (const std::string& word : {"cat", "dog", "cat"}) {
        ++counts[word];  // A missing key starts at 0.
    }

    assert(counts.size() == 2);
    assert(counts.at("cat") == 2);
    assert(counts.contains("dog") && !counts.contains("owl"));

    auto it = counts.find("cat");
    assert(it != counts.end() && it->second == 2);

    int total = 0;
    for (const auto& [word, count] : counts) total += count;
    assert(total == 3);
}
```

There are several ways to read a key, and they behave differently:

- `m[key]` returns the value, **creating** the key first if it is missing.
  For an `int` value the new entry starts at 0, which makes counting easy.
  It also means a "read" of a missing key silently adds it.
- `m.contains(key)` (C++20) answers yes or no without changing the map.
  `m.count(key)` gives the same answer as 0 or 1.
- `m.find(key)` returns an **iterator**, a position in the container, or
  `end()` if the key is absent. `it->first` is the key and `it->second`
  is the value. Check against `end()` before using it.
- `m.at(key)` returns the value, or throws `std::out_of_range` if missing.

`m.erase(key)` removes a key. A range-based `for` with
`[word, count]` names each entry's key and value directly.

## Sets store membership

```cpp
std::unordered_set<int> seen;
seen.insert(4);
seen.insert(4);  // Already present: no change.
assert(seen.size() == 1 && seen.contains(4));
```

`insert` returns a pair whose `second` is `true` if the key was new. That
lets you test and insert in one call: `if (!seen.insert(x).second)` means
`x` was a duplicate.

## Cost and order

A **hash function** turns a key into a number, which picks a **bucket**
where the key is stored. Different keys can land in the same bucket. On
average each bucket holds few keys, so operations are O(1). In the worst
case, when many keys collide, they become O(n). Hashing a long string key
also takes time proportional to its length.

Iteration order is unspecified and can change as the map grows. If you
need sorted keys, use `std::map` or sort the keys afterwards. If you know
roughly how many keys you will add, `m.reserve(n)` prepares enough
buckets up front and avoids repeated regrowth.

## Keys without a hash

Numbers, `char`, and `std::string` work as keys out of the box.
`std::pair` and `std::tuple` do **not**, so
`std::unordered_map<std::pair<int, int>, int>` fails to compile. Common
fixes in DSA problems:

- Encode the pair into one number, such as `1LL * row * cols + col` for a
  grid cell, or into a string.
- Use `std::map` or `std::set`, which need ordering, not hashing, and
  already accept pairs.
- Write a custom hash function. Keys that compare equal must hash equally.
