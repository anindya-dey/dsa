---
title: "std::optional"
summary: "A value that may be missing: returning not-found without magic values like -1."
---

A function that searches for something needs a way to say "not found".
A common habit is a special value such as `-1`, but that only works when
`-1` can never be a real answer. `std::optional<T>` from `<optional>`
(C++17) holds either a `T` or nothing, so absence is part of the type.

## Returning a value or nothing

```cpp
#include <cassert>
#include <optional>
#include <vector>

std::optional<int> firstNegative(const std::vector<int>& v) {
    for (int x : v) {
        if (x < 0) return x;
    }
    return std::nullopt;  // Nothing found.
}

int main() {
    std::optional<int> found = firstNegative({4, -2, -7});
    assert(found.has_value() && *found == -2);

    std::optional<int> none = firstNegative({1, 2});
    assert(!none);
    assert(none.value_or(0) == 0);
}
```

Return a `T` to fill the optional, or `std::nullopt` to leave it empty.
The caller has a few ways to read it:

- `if (opt)` or `opt.has_value()` tests whether a value is there.
- `*opt` reads the value. Only do this after checking: reading an empty
  optional with `*` is undefined behavior.
- `opt.value()` reads the value, or throws `std::bad_optional_access` if
  it is empty.
- `opt.value_or(fallback)` returns the value, or `fallback` if empty.

A common call-site shape tests and reads in one place:

```cpp
if (auto neg = firstNegative({3, -1})) {
    assert(*neg == -1);
}
```

## When to use it

Use `optional` when "no answer" is a normal outcome, such as a lookup that
may miss or a search with no match. Use an exception for real errors, such
as a broken input file.

The value is stored inside the optional itself, with no separate
allocation, so it is cheap to return. For a pointer such as `TreeNode*`,
`nullptr` already means "nothing", so you do not need an optional. Many
LeetCode signatures still require `-1` or an empty vector; follow the
signature there, and use `optional` in your own helper functions.
