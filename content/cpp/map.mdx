title: "std::map / std::set"
summary: "Sorted keys: lookup, smallest and largest, lower_bound ranges, multiset duplicates, and custom order."
---

`std::map` stores one value for each unique key and keeps the keys
sorted. `std::set` keeps sorted unique keys with no values. Use them when
you need order: the smallest key, the largest, or every key in a range.
Lookup, insertion, and erasure take O(log n).

## Sorted lookup

```cpp
#include <cassert>
#include <map>
#include <set>
#include <string>
#include <vector>

int main() {
    std::map<std::string, int> stock = {{"pear", 4}, {"apple", 1}, {"melon", 3}};
    stock["kiwi"] = 2;  // Inserts, or overwrites an existing value.

    assert(stock.begin()->first == "apple");  // Smallest key.
    assert(stock.rbegin()->first == "pear");  // Largest key.
    assert(stock.at("melon") == 3);
    assert(stock.contains("kiwi") && !stock.contains("fig"));

    std::vector<std::string> inOrder;
    for (const auto& [name, count] : stock) inOrder.push_back(name);
    assert((inOrder == std::vector<std::string>{"apple", "kiwi", "melon", "pear"}));

    std::set<int> s = {5, 1, 3};
    assert(*s.begin() == 1 && *s.rbegin() == 5);
}
```

The reading rules match `unordered_map`: `[]` creates a missing key,
`contains` and `count` only check, `find` returns an iterator or `end()`,
and `at` throws for a missing key. In a map, `it->first` is the key and
`it->second` the value; in a set, `*it` is the key.

Iterating visits keys in ascending order. `begin()` is the smallest and
`rbegin()` the largest; dereference them only when the container is
nonempty. Strings sort by
character code, so `"Zoo"` comes before `"apple"`.

## Finding neighbors and ranges

`lower_bound(x)` returns the first key `>= x`. `upper_bound(x)` returns the
first key `> x`. Either returns `end()` if no such key exists.

```cpp
std::set<int> times = {10, 20, 30, 40};
assert(*times.lower_bound(20) == 20);  // First >= 20.
assert(*times.upper_bound(20) == 30);  // First > 20.
assert(times.lower_bound(50) == times.end());

auto it = times.lower_bound(25);       // 30.
assert(*std::prev(it) == 20);          // Largest key < 25.
```

To find the largest key below `x`, step back from `lower_bound(x)` with
`std::prev`, after checking that the result is not `begin()`. To visit
every key in `[a, b)`, loop from `lower_bound(a)` to `lower_bound(b)`.
Each search is O(log n). Always use these member functions: the free
`std::lower_bound` on a set walks the tree one step at a time, which is O(n).

## Duplicates: multiset and multimap

A set keeps one copy of each key. `std::multiset` keeps duplicates, which
helps when you need a sorted window of values that may repeat:

```cpp
std::multiset<int> window = {3, 1, 3};
window.erase(window.find(3));  // Removes ONE 3.
assert(window.count(3) == 1);
window.erase(3);               // Removes EVERY 3.
assert(window.count(3) == 0 && window.size() == 1);
```

`erase(key)` removes all copies, so erase through `find` when you mean one.
`std::multimap` does the same for key-value pairs, allowing one key to
appear with several values.

## Custom order

Pass a comparator to change the order. `std::greater<int>` from
`<functional>` sorts in descending order:

```cpp
std::set<int, std::greater<int>> desc = {10, 30, 20};
assert(*desc.begin() == 30);
```

Two keys count as the same key when neither comes before the other under
the comparator. A comparator must use a strict `<`-style test, never `<=`.

Choose `map` or `set` when order matters. If you only need lookup, an
unordered container is usually faster, at O(1) on average.
