title: "std::deque"
summary: "A double-ended queue: O(1) changes at both ends, indexed access, and its use in sliding windows."

Adding to the front of a vector shifts every element. `std::deque`, short
for **double-ended queue** and pronounced "deck", adds and removes at
either end in O(1) and still supports O(1) access by index. It lives in
the `<deque>` header.

## Working with both ends

```cpp
#include <cassert>
#include <deque>

int main() {
    std::deque<int> d = {2, 3};
    d.push_front(1);
    d.push_back(4);
    assert((d == std::deque<int>{1, 2, 3, 4}));
    assert(d[1] == 2);

    d.pop_front();
    d.pop_back();
    assert(d.front() == 2 && d.back() == 3);
    assert(d.size() == 2);
}
```

`push_front` and `push_back` add an element; `pop_front` and `pop_back`
remove one. The pops return nothing, so read `front()` or `back()` first if
you need the value. Calling `front`, `back`, or a pop on an empty deque is
undefined behavior, so check `empty()` first.

`d[i]` is unchecked and `d.at(i)` throws for a bad index, as with vector.
Inserting or erasing in the middle is O(n) because elements shift.

## How it differs from vector

A deque typically stores elements in a series of fixed-size blocks rather
than one buffer. That is how it grows at the front without moving
everything. It also means the elements are **not contiguous**: there is no
`data()` pointer and no `reserve()`. Indexing is still O(1), but a little
slower than a vector's.

Changing a deque can invalidate saved iterators. Adding at either end
keeps references to existing elements valid but invalidates all
iterators. Changing the middle invalidates everything. Indices shift too:
after `push_front`, the old `d[0]` is now `d[1]`.

## When a deque fits

Use a deque when you need both ends, as in a
[sliding-window maximum](/dsa/patterns/monotonic-structures/sliding-window-maximum).
That solution keeps indices of candidate elements: it drops expired
indices from the front and smaller candidates from the back. Each index
enters once and leaves at most once, so the total work is O(n). If you
only add at the back, a vector is simpler and faster.

## Related C++ tools

- [std::vector](/cpp/vector) offers contiguous storage and fast back growth.
- [std::stack / std::queue](/cpp/stack-queue) wraps a deque in a simpler interface.
