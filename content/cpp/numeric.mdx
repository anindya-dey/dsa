A handful of small functions save you from writing the same loops in
every solution. Most live in `<numeric>`, `<algorithm>`, `<cmath>`, and
`<limits>`.

## Sums, sequences, and divisors

```cpp
#include <algorithm>
#include <cassert>
#include <climits>
#include <cmath>
#include <limits>
#include <numeric>
#include <vector>

int main() {
    std::vector<int> v = {4, 1, 3};
    assert(std::accumulate(v.begin(), v.end(), 0LL) == 8);

    std::vector<int> idx(3);
    std::iota(idx.begin(), idx.end(), 0);  // {0, 1, 2}
    std::sort(idx.begin(), idx.end(), [&](int a, int b) { return v[a] < v[b]; });
    assert((idx == std::vector<int>{1, 2, 0}));  // Indices by value.

    assert(std::gcd(12, 18) == 6 && std::lcm(4, 6) == 12);
    assert(std::max({3, 9, 2}) == 9);
    assert(std::clamp(15, 0, 10) == 10);
    assert(std::abs(-5) == 5);
    assert(std::numeric_limits<int>::max() == INT_MAX);
}
```

`std::accumulate(begin, end, start)` adds every element to `start`. The
sum uses the type of `start`, so `0` sums in `int` and can overflow, while
`0LL` sums in `long long`. Use `0LL` unless you are sure the total fits.

`std::iota(begin, end, 0)` fills a range with 0, 1, 2, and so on. Combined
with a sort that compares `v[a] < v[b]`, it gives the indices of `v` in
order of their values, without moving `v` itself.

`std::gcd` and `std::lcm` (C++17) compute the greatest common divisor and
least common multiple. `std::lcm` can overflow for large inputs.

## min, max, and abs

`std::min(a, b)` and `std::max(a, b)` need both arguments to have the same
type. `std::min(x, v.size())` with an `int` `x` does not compile, because
`size()` is unsigned; convert one side, as in
`std::min(x, (int)v.size())`. Pass braces to compare more than two values:
`std::max({a, b, c})`. `std::clamp(x, lo, hi)` limits `x` to the range
`[lo, hi]`.

`std::abs(INT_MIN)` is undefined behavior, because the positive value does
not fit in an `int`.

## Limits and "infinity"

`std::numeric_limits<int>::max()` from `<limits>`, also spelled `INT_MAX`
in `<climits>`, is the usual starting value when you track a minimum, and
`INT_MIN` when you track a maximum. In shortest-path code it often marks
"unreachable". Never add to it: `INT_MAX + 1` overflows. Check
`dist[u] != INT_MAX` before computing `dist[u] + w`, or choose a smaller
sentinel such as `1e9` that leaves room for additions.

## pow and sqrt return doubles

`std::pow` and `std::sqrt` from `<cmath>` work in floating point. A result
such as `std::pow(10, 9)` is a `double`, and converting a large or inexact
result back to an integer can round down by one. For integer powers,
multiply in a loop with `long long`, or use fast exponentiation with a
modulus. To test whether `n` is a perfect square, compute
`long long r = std::sqrt(n)` and then check `r * r == n`, adjusting `r` by
one if needed.
