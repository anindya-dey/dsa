A `std::priority_queue` always lets you see and remove its
highest-priority element. It is a **heap**: `push` and `pop` take
O(log n), and `top` takes O(1). It lives in the `<queue>` header.
The one fact to remember: **by default it is a max-heap**, so `top()` is
the largest element.

## Max-heap and min-heap

```cpp
#include <cassert>
#include <functional>
#include <queue>
#include <utility>
#include <vector>

int main() {
    std::priority_queue<int> maxHeap;
    for (int x : {3, 1, 4}) maxHeap.push(x);
    assert(maxHeap.top() == 4);
    maxHeap.pop();          // Removes 4; returns nothing.
    assert(maxHeap.top() == 3);

    std::priority_queue<int, std::vector<int>, std::greater<int>> minHeap;
    for (int x : {3, 1, 4}) minHeap.push(x);
    assert(minHeap.top() == 1);

    using Item = std::pair<int, int>;  // (distance, node)
    std::priority_queue<Item, std::vector<Item>, std::greater<Item>> nearest;
    nearest.push({5, 0});
    nearest.push({2, 7});
    assert(nearest.top().second == 7);  // Smallest distance first.
}
```

For a min-heap, write out all three template arguments: the element type,
`std::vector` of that type, and `std::greater`. Pairs compare by `first`,
then `second`, so a min-heap of `(distance, node)` pairs pops the nearest
node first. This is the usual form for Dijkstra's algorithm.

As with stack and queue, `pop()` returns nothing, so read `top()` first.
Calling `top` or `pop` on an empty heap is undefined behavior.

## Custom comparators

The comparator answers "does `a` have **lower** priority than `b`?" The
heap keeps lower-priority elements below, so `std::less` (the default)
puts the largest on top, and `std::greater` puts the smallest on top.
A lambda works the same way:

```cpp
auto byLength = [](const std::string& a, const std::string& b) {
    return a.size() > b.size();  // Shorter strings have higher priority.
};
std::priority_queue<std::string, std::vector<std::string>, decltype(byLength)>
    shortest(byLength);
shortest.push("banana");
shortest.push("fig");
assert(shortest.top() == "fig");
```

`decltype(byLength)` names the lambda's type, and passing `byLength` to
the constructor gives the heap its comparator.

## What it cannot do

You can only see the top. There is no iteration, no search, and no way to
change the priority of an element already inside. Two standard
workarounds cover most problems:

- **Top k.** To keep the k largest values, use a min-heap and pop whenever
  its size exceeds k. The top is then the kth largest. This costs
  O(n log k).
- **Lazy deletion.** To "update" a priority, push a new entry and leave
  the old one. When an outdated entry reaches the top, skip it. Dijkstra
  does this by ignoring a popped distance larger than the best known one.

Building a heap from an existing vector,
`std::priority_queue<int> pq(v.begin(), v.end())`, takes O(n), faster
than n separate pushes.
