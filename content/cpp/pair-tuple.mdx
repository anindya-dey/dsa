---
title: "std::pair / std::tuple / std::array"
summary: "Small fixed groups of values: structured bindings, field-by-field comparison, and fixed-size arrays."
---

These three types group a fixed number of values. `std::pair` holds two
values, possibly of different types. `std::tuple` holds any number.
`std::array` holds a fixed number of values of one type. Pairs and tuples
come from `<utility>` and `<tuple>`; arrays from `<array>`.

## pair

```cpp
#include <algorithm>
#include <array>
#include <cassert>
#include <string>
#include <tuple>
#include <utility>
#include <vector>

int main() {
    std::pair<std::string, int> p = {"ada", 36};
    assert(p.first == "ada" && p.second == 36);

    auto [name, age] = p;  // Structured binding: copies both fields.
    assert(name == "ada" && age == 36);

    std::vector<std::pair<int, int>> v = {{2, 1}, {1, 9}, {2, 0}};
    std::sort(v.begin(), v.end());
    assert((v == std::vector<std::pair<int, int>>{{1, 9}, {2, 0}, {2, 1}}));
}
```

A **structured binding**, `auto [a, b] = p;` (C++17), gives each field its
own name. Write `auto& [a, b]` to refer to the original fields instead of
copying them. The same syntax names the key and value in
`for (const auto& [key, value] : someMap)`.

Pairs compare **lexicographically**: by `first`, and by `second` only when
the firsts are equal. That is why sorting a vector of pairs sorts by the
first field and breaks ties with the second, and why a heap of
`(distance, node)` pairs orders by distance. To sort by one field
descending, store it negated, or write a comparator.

## tuple

```cpp
std::tuple<int, std::string, double> t = {1, "x", 2.5};
auto [id, label, score] = t;
assert(std::get<0>(t) == 1 && label == "x");

int a = 0, b = 0;
std::tie(a, b) = std::make_pair(3, 4);  // Assigns to existing variables.
assert(a == 3 && b == 4);
```

`std::get<i>(t)` reads field `i`, counting from 0. Tuples also compare
field by field. `std::tie(a, b)` builds a tuple of references, which can
receive values or compare several fields at once in a comparator. For
anything beyond three or four fields, a small `struct` with named members
is easier to read.

## array

```cpp
std::array<int, 26> counts{};  // 26 zeros: the {} matters.
for (char c : std::string("hello")) ++counts[c - 'a'];
assert(counts['l' - 'a'] == 2 && counts.size() == 26);
```

The size is part of the type and cannot change. The elements live inside
the `std::array` object itself, with no separate allocation. Without `{}`,
a local `std::array<int, 26>` holds garbage values, and reading them is
undefined behavior.

Unlike a plain C array, a `std::array` knows its `size()`, copies on
assignment, compares with `==`, and can be returned from a function. Unlike
a vector, it never grows. It suits letter counts, direction tables such as
`std::array<int, 4> dr = {-1, 1, 0, 0}`, and trie child pointers.
