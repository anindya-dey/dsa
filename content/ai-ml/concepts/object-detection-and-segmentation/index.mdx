[Image classification](/ai-ml/concepts/image-classification) says
*what* is in an image; **object detection** says *what and where* —
it finds every object and draws a bounding box around it.
**Segmentation** goes further, outlining objects *per pixel* (a mask
for each object, or a label for every pixel). Together they are the
core of applied vision: self-driving (detect cars, pedestrians,
lanes), medical imaging (locate tumors), retail (count products),
robotics (find objects to grasp). They build on classification
features but add the *localization* problem, which is what makes them
harder.

## Detection: what and where

The output is a set of boxes, each with a class and a confidence.
The core challenge: an image has a *variable* number of objects, at
*unknown* positions and sizes — so the model cannot just output a
fixed-size answer. The standard approach: generate many **candidate
regions** (or a dense grid of predictions) and, for each, predict
"is there an object here, what is it, and how should the box be
adjusted?" — then **suppress overlapping duplicates** (a step called
non-maximum suppression: keep the best box per object, discard its
near-duplicates).

The evolution: **two-stage detectors** (propose regions, then classify
each — accurate, slower; the R-CNN family) → **one-stage detectors**
(predict boxes and classes directly from a grid, in one pass — faster,
the YOLO/SSD family, and the modern default for real-time) → **anchor-free
and transformer-based detectors** (DETR: treat detection as a
sequence-prediction problem with
[attention](/ai-ml/concepts/attention-mechanism)). The accuracy-versus-speed
tradeoff is the central design axis, because detection often runs on
live video where latency is critical.

## Segmentation: per-pixel understanding

Segmentation assigns a label to *every pixel*, which gives precise
outlines rather than boxes. Variants:

- **Semantic segmentation** (every pixel gets a *class* — all cars are
  one label, so two adjacent cars merge).
- **Instance segmentation** (each *object* gets its own mask — the two
  cars stay distinct).
- **Panoptic segmentation** (both: all objects, all classes).

The classic architecture is the **encoder-decoder** (downsample to
capture context, then upsample back to full resolution to produce the
pixel-level mask — the U-Net shape, which is also dominant in medical
imaging), and transformers (ViT-based) now compete there too.

## Why these are harder (and what they share)

Both tasks require *spatial reasoning* — not just "what is this
image?" but "what is where?" — which means the model needs to preserve
positional information that a plain classifier discards. They also
face the same real-world issues: **class imbalance** (most of an image
is background), **small objects** (hard to detect), **crowded scenes**
(overlapping objects), and **the annotation cost** (drawing boxes and
masks is expensive — a major practical constraint, and the reason
[labeling](/ai-ml/systems/data-labeling-annotation) pipelines matter).

## The multimodal turn

The frontier is **grounded and open-vocabulary** detection: instead of
a fixed set of classes, detect objects described in *text* ("find the
red umbrella") by combining vision with a
[vision-language model](/ai-ml/concepts/vision-language-models). This
generalizes detection from "the classes we trained on" to "whatever
you can describe", and it is where detection, segmentation, and
language understanding are converging.
